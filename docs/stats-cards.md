# Stats maintenance

Stats and Top Languages are generated by `Update Profile Cards` daily at 00:17 UTC (09:17 JST), or on manual dispatch. GitHub may delay scheduled runs.

## Published statistics

All Stats queries include accessible private repositories. Only the five numeric totals and the update date are published in the light and dark SVG cards.

| Row | Definition |
| --- | --- |
| Total Stars | Current sum of stars received by owned, non-fork public and private repositories, including archived repositories. Every repository page is fetched. |
| Total Commits | Sum of GitHub's `totalCommitContributions` across every year returned by `contributionYears`, through the time of the update. Each query covers a separate calendar year. |
| Total PRs | `user.pullRequests.totalCount`, with no visibility or state filter. |
| Total Issues | `user.issues.totalCount`, with no visibility or state filter. |
| Contributed to | GitHub's `repositoriesContributedTo.totalCount`, including owned repositories and COMMIT, ISSUE, PULL_REQUEST, and REPOSITORY contribution types. GitHub defines this as recently contributed repositories; this is not a lifetime total of every repository ever touched. |

Commits follow [GitHub's contribution criteria](https://docs.github.com/en/account-and-profile/reference/profile-contributions-reference), including account attribution and default/gh-pages branch rules. They are not a count of every commit on every branch. Repositories and activity no longer accessible to the account cannot be recovered from these APIs.

`restrictedContributionsCount` mixes multiple kinds of activity. It is never added to the commit total. If a yearly query still reports restricted activity, the update stops instead of publishing incomplete counts. API errors, missing permissions, incomplete repository pagination, or a token belonging to another account also stop publication.

No private repository names, URLs, descriptions, source files, commit messages, PR/issue titles, or author details are requested. Raw API responses and credentials are not written to files or printed in logs. The wide activity graph remains supplied by the public service; [Top Languages](language-cards.md) retains its separate metadata-only token.

## Stats credential

The Stats step expects `PROFILE_STATS_TOKEN` in this repository's Actions secrets. Use a dedicated classic personal access token owned by `TERUZvxght`, with `repo` and `read:user` scopes.

**The classic `repo` scope includes repository write access, even though this script performs only read-only GraphQL queries.** It cannot be narrowed to individual repositories. The account owner approved these broader scopes for the dedicated `profile-stats-private` token. No `workflow`, `delete_repo`, or additional account/organization scopes were requested. The configured token has no expiration, as requested by the owner.

GitHub documents the [read:user requirement for private contribution breakdowns](https://docs.github.com/en/graphql/reference/users#contributionscollection). The upstream Stats project also documents the [fine-grained token limitation for private commits](https://github.com/anuraghazra/github-readme-stats#first-step-get-your-personal-access-token-pat). Scope meanings are documented in [GitHub's scope reference](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/scopes-for-oauth-apps).

The Stats secret is exposed only to its aggregation step, not checkout, tests, language generation, or publication. The built-in workflow token publishes only the four generated SVG files. Neither private-access token is sent to an external card service.

## Verification

```sh
python3 -m unittest discover -s scripts -p 'test_*.py'
python3 scripts/update_stats.py --owner TERUZvxght
```

The second command requires GitHub CLI authentication with both Stats scopes. Without them, it stops before generating assets. Do not enable shell tracing or HTTP debug logging. After configuring the secret, dispatch `Update Profile Cards`, verify the run succeeds, and inspect both themes on the profile.
